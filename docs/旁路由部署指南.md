# 旁路由部署指南

面向 ByPassWrt 固件（ImmortalWrt 24.10 / x86_64）。默认地址 `192.168.2.2`，网关 `192.168.2.1`。

---

## 一、旁路由到底是个什么东西

主路由继续负责拨号、发 IP、连 WiFi，**不动它**。旁路由只是挂在局域网里的一台机器，
谁想走代理，就把网关指向它。

```
          光猫 / 宽带
              │
        ┌─────┴─────┐
        │   主路由   │  192.168.2.1   拨号 + DHCP + WiFi
        └─────┬─────┘
              │  一根网线
        ┌─────┴─────┐
        │   旁路由   │  192.168.2.2   只干代理和 DNS
        └───────────┘
              ↑
     客户端把网关改成 .2 就走代理，改回 .1 就直连
```

这么做的好处：**旁路由挂了不影响全家上网**。把网关改回主路由就恢复，
比"主路由刷第三方固件"稳得多。

## 二、刷机

### 物理机（软路由 / 小主机 / 旧电脑）

1. 下载 `*-squashfs-combined-efi.img.gz`（2015 年后的机器基本都是 UEFI）
   老机器 / 传统 BIOS 用不带 `-efi` 的那个
2. 用 [balenaEtcher](https://etcher.balena.io/) 或 [Rufus](https://rufus.ie/) 写入硬盘/U盘
   - Etcher 可以直接写 `.img.gz`，不用解压
3. BIOS 里关掉 **Secure Boot**（OpenWrt 的引导没签名，开着起不来）
4. 从写好的盘启动

### PVE（Proxmox）

```bash
# 1. 上传并解压
gunzip immortalwrt-x86-64-generic-squashfs-combined-efi.img.gz

# 2. 建一台空虚拟机（假设 VMID=100），不要挂任何磁盘
#    CPU 类型选 host，网卡型号选 VirtIO 或 E1000

# 3. 把镜像导入成虚拟机磁盘
qm importdisk 100 immortalwrt-x86-64-generic-squashfs-combined-efi.img local-lvm

# 4. 在 PVE 界面把这块 "未使用的磁盘 0" 添加为 SCSI 或 SATA，并设为启动项
# 5. 选项 → BIOS 改成 OVMF(UEFI)，对应 -efi 镜像；用非 efi 镜像则保持 SeaBIOS
```

网卡建议直通或桥接到和主路由同一个网桥（通常是 `vmbr0`）。

### ESXi / VirtualBox / VMware

直接用 `.vmdk` 文件，新建虚拟机时选择"使用现有虚拟磁盘"。
网卡模式选 **桥接（Bridged）**，不要用 NAT。

## 三、首次接入

刷完开机后，旁路由固定在 `192.168.2.2`，但你的电脑这会儿可能还在别的网段。

**最省事的办法**：电脑网线直连旁路由，手动配一个静态 IP：

| 项 | 值 |
| --- | --- |
| IP | `192.168.2.100` |
| 子网掩码 | `255.255.255.0` |
| 网关 | `192.168.2.2` |
| DNS | `192.168.2.2` |

浏览器打开 <http://192.168.2.2>，用户名 `root`，**密码为空**。

### 进去先做三件事

1. **改密码**：系统 → 管理权 → 主机密码。或者 SSH 进去敲 `passwd`
2. **确认网段对不对**：如果你家主路由不是 `192.168.2.1`（很多路由器默认 `192.168.1.1`，
   小米常见 `192.168.31.1`），去 网络 → 接口 → LAN，把 IPv4 地址和网关一起改掉，
   改完旁路由的管理地址也跟着变
3. **对时**：系统 → 系统 → 时间同步，确认时间正确。**时间不对会导致所有 TLS 节点连不上**

然后把旁路由接回主路由的 LAN 口，电脑网络设置改回自动获取。

## 四、让客户端走旁路由

三种方式，按侵入性从小到大排：

### 方式 A：单台设备手动指（推荐先用这个验证）

只改想走代理的那台电脑/手机：

- 网关：`192.168.2.2`
- DNS：`192.168.2.2`

好处是出问题只影响这一台，改回 `.1` 立刻恢复。**第一次配置强烈建议用这个方式验证。**

### 方式 B：主路由 DHCP 下发旁路由为网关

在主路由的 DHCP 设置里，把下发的网关和 DNS 都改成 `192.168.2.2`。
不同品牌位置不一样，一般在「LAN 设置 / DHCP 服务器」里。有些便宜路由器不给改，那就用方式 C。

### 方式 C：旁路由接管 DHCP

1. **先关掉主路由的 DHCP 服务**（两个 DHCP 同时开，客户端会随机拿到其中一个的地址，
   表现为"时好时坏"，非常难排查）
2. 编辑 `files/etc/uci-defaults/99-bypass-router`，把 `SERVE_DHCP="0"` 改成 `"1"`，重新编译刷机

   或者已经刷好的机器直接执行：

   ```bash
   uci set dhcp.lan.ignore='0'
   uci set dhcp.lan.start='100'
   uci set dhcp.lan.limit='150'
   uci set dhcp.lan.force='1'
   uci -q delete dhcp.lan.dhcp_option
   uci add_list dhcp.lan.dhcp_option='3,192.168.2.2'   # 网关
   uci add_list dhcp.lan.dhcp_option='6,192.168.2.2'   # DNS
   uci commit dhcp && /etc/init.d/dnsmasq restart
   ```

方式 C 全自动，但旁路由一挂全家断网，量力而行。

## 五、配置 PassWall

固件里 PassWall 的分流规则、端口、远程 DNS 都已经调好了，**你只需要加节点**。

1. **服务 → PassWall → 节点列表**
   - 有订阅链接：「订阅」标签页 → 添加订阅地址 → 保存 → 「手动订阅」
   - 单个节点：「添加」，或用分享链接（`vmess://` / `ss://` / `trojan://`）导入
2. 回到 **基本设置**，在「主节点」里选一个刚导入的节点
3. 勾选 **启用**，保存并应用
4. 打开一个境外网站验证

### 已经帮你配好的部分（不用动）

| 设置项 | 值 | 为什么 |
| --- | --- | --- |
| TCP/UDP 转发端口 | `1:65535` | 全端口代理，游戏和小众应用不漏 |
| 转发方式 | TProxy | 24.10 用 nftables，TProxy 比 REDIRECT 更完整（UDP 也能转） |
| 远程 DNS | OpenDNS DoH | 境外域名走加密 DNS，防污染 |
| 直连 DNS | `223.5.5.5` | 国内域名走阿里，快 |
| 过滤 IPv6 代理 | 开启 | 防止 IPv6 绕过代理直连泄露 |
| DNS 劫持 | 开启 | 客户端写死 `8.8.8.8` 也会被拉回来 |

### 想换 OpenClash

固件里也带了 OpenClash，但**不要和 PassWall 同时启用**——两个都在改 nftables 规则，
一定打架。先把 PassWall 停掉，再启用 OpenClash。

## 六、关于 OpenDNS

固件里 OpenDNS 出现在两个地方，作用不一样：

**1. SmartDNS 的 `opendns` 分组**（境外域名的日常解析）

```
208.67.222.222 / 208.67.220.220     UDP 5353、TCP 443
https://doh.opendns.com/dns-query   DoH
2620:119:35::35 / 2620:119:53::53   IPv6
```

规则写在 `/etc/smartdns/custom.conf`，Google、GitHub、OpenAI 这些域名会指到这个组。
改完执行 `/etc/init.d/smartdns restart` 生效。

**2. PassWall 的远程 DNS**（开启代理后，境外域名的解析）

`https://doh.opendns.com/dns-query,208.67.222.222` —— 逗号后面是 bootstrap IP，
用来解析 `doh.opendns.com` 这个域名本身，不然会死循环。

### 想开家长控制（FamilyShield）

OpenDNS 的 FamilyShield 会拦截成人内容，换成这组地址即可：

| 类型 | 地址 |
| --- | --- |
| IPv4 | `208.67.222.123` / `208.67.220.123` |
| IPv6 | `2620:119:35::123` / `2620:119:53::123` |
| DoH | `https://doh.familyshield.opendns.com/dns-query` |
| DoT | `dns.familyshield.opendns.com`（853 端口） |

在 LuCI「服务 → SmartDNS → 上游服务器」里把 `opendns` 组的地址替换掉就行。

### 想用 OpenDNS 的自定义拦截策略

需要去 <https://dashboard.opendns.com> 注册账号、绑定自己的公网 IP。
家宽 IP 会变，得配合 DDNS 更新——固件里带了 `luci-app-ddns`，OpenDNS 也在它的服务商列表里。

## 七、排障速查

| 症状 | 先查这里 |
| --- | --- |
| 刷完连不上 `192.168.2.2` | 电脑是不是还在别的网段？手动配 `192.168.2.100/24` 试试 |
| 开机配置好像没生效 | `cat /tmp/bypass-setup.log` 看首次配置脚本的执行记录 |
| 能 ping 通 IP，网页打不开 | DNS 问题：`nslookup baidu.com 192.168.2.2` |
| 开了 PassWall 就全断 | 节点没配好或已失效。先停掉 PassWall 恢复上网，再排查节点 |
| 境外网站时好时坏 | 时间对不对？`date`。时间偏差超过几分钟，TLS 握手会失败 |
| 网速只有几 Mbps | 确认流量分载是关的（旁路由必须关），看看是不是节点本身慢 |
| 客户端拿到错误的网关 | 主路由的 DHCP 是不是还开着？两个 DHCP 会打架 |
| 某些设备不走代理 | 有些设备（电视盒子、IoT）会写死 DNS，需要开 PassWall 的 DNS 劫持 |

### 常用命令

```bash
cat /tmp/bypass-setup.log        # 首次开机配置日志
logread -e passwall              # PassWall 日志
logread -e smartdns              # SmartDNS 日志
/etc/init.d/smartdns status      # SmartDNS 运行状态
nft list ruleset | head -50      # 当前防火墙规则
ip route                         # 路由表，确认默认路由指向主路由
cat /etc/config/network          # 网络配置
```

### 救砖：改错配置连不上了

物理机接显示器和键盘，开机时选 **failsafe** 模式；或者在 grub 菜单里选。
进去后：

```bash
mount_root
firstboot -y     # 恢复出厂设置
reboot -f
```

虚拟机的话，直接删掉重新导入镜像更快。

## 八、几个容易踩的坑

**别在旁路由上开 DHCP 又不关主路由的**。两个 DHCP 服务器抢着回应，客户端拿到谁的地址全看运气，
表现出来就是"有的设备能用有的不能"，排查起来极其痛苦。

**别开硬件流量分载**。LuCI 里「网络 → 防火墙」有个「软件流量分载 / 硬件流量分载」，
开了之后数据包会绕过 netfilter 直接转发，透明代理就完全失效了。固件默认已经关掉，别手贱去开。

**别同时启用 PassWall 和 OpenClash**。两个都要接管 nftables 的转发规则，同时开必然冲突。

**时间一定要对**。旁路由没有 RTC 电池的话（虚拟机、部分软路由），每次开机时间都是错的，
必须等 NTP 同步完成才能连节点。固件已经把 NTP 服务器换成了国内的（阿里、腾讯），
但如果开机瞬间网络还没通，可能要等一会儿。

**IPv6 的坑**。如果主路由下发了 IPv6，客户端可能优先走 IPv6 直连，绕过旁路由的代理。
固件默认开了 PassWall 的「过滤 IPv6 代理」来避免泄露；彻底一点的做法是在主路由上关掉 IPv6。
